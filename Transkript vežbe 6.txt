        private static string GetDateStringInRange(int minDays, int maxDays, Func<DateTime, bool> predicate)
        {
            for (int i = minDays; i <= maxDays; i++)
            {
                DateTime date = DateTime.Today.AddDays(i);
                if (predicate == null || predicate(date))
                {
                    return date.ToString("yyyy-MM-dd");
                }
            }

            throw new Exception("No suitable date found in range.");
        }

        private static bool IsWeekday(DateTime date)
        {
            return date.DayOfWeek != DayOfWeek.Saturday && date.DayOfWeek != DayOfWeek.Sunday;
        }

U  #CartTest.cs  u liniji 217, test public void Calculate_DaysLessOrEqual3_Discount8PercentApplied() nije uspešan. U čemu je greška?

------------------------------------------

The failure is caused by the assumed 8% discount not always being applied.
That discount in Cart.Calculate only applies when all of these are true:
•	Delivery date is weekday (isNotWeekend == true)
•	Size > 8
•	laptop_counter >= 1 && laptop_counter < 8
Your test expects the 8% discount (budget 380.8), but if the selected date falls on a weekend, isNotWeekend becomes false, so no discount is applied, and the budget becomes:
2000 - 1760 = 240

So the test fails.

Why it happens: the date is generated dynamically and depends on the current day. If the generated date is a weekend, the discount is skipped.
Fix: make the test deterministic by forcing a weekday date (e.g., explicitly compute the next weekday) or adjust expected value based on actual day.

Nakon moje izmene, Test public void Calculate_DaysLessOrEqual3_Discount10PercentApplied() jos uvek nije uspesan u #CartTest.cs
-----------------------------------------

Problem je u očekivanoj vrednosti u testu.
Za taj scenario se primenjuje 10% popusta, ne 20%, pa je preostali budžet drugačiji.
Računica:
•	Ukupno: 3*100 + 3*1200 + 3*800 = 6300
•	10% popust → 6300 * 0.9 = 5670
•	Budžet 7000 → 7000 - 5670 = 1330
Zato test mora očekivati 1330, a ne 1960.
Primeni ovu izmenu:
